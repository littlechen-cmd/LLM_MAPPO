# 验证 — 正式仿真环境训练配置

## 完成标准

- [ ] 场景矩阵准确对应已确认的 tiny 3/3/2、现有 5-AGV 场景及正式图 8/8/10；
  正式地图哈希及更正后的 896 个可通行格均有记录。所有站点坐标唯一、可达，且不与
  货架重叠。
- [ ] 每个场景初始活跃任务数等于 AGV 数，每完成一单即补一单。同场景训练与评估
  负载一致，采用相同的候选 `max_steps`，不会因 `task_target` 提前终止。
- [ ] 四种方法能够一致地加载临时场景配置，正式长训练入口仍拒绝这些配置。不同场景、
  不同配置或维度的 checkpoint 不得通过部分加载或静默迁移互相混用。
- [ ] FP Critic 的货架槽位与实际地图一致，尤其正式图为 504；训练 worker 与主进程
  生成相同维度，不再沿用固定 144 槽位。
- [ ] 16 个 worker、每 worker 64 步的完整 rollout 记录 1,024 个累计环境
  transition；最后一个不足完整长度的批次也须正确计数。
- [ ] 固定 seed 的两次运行具有相同初态、任务流和指定动作轨迹。每个场景至少展示一轮
  完整任务循环；正式 8-AGV 场景还须覆盖站点使用、充电和安全行为。
- [ ] 诊断结果与负责人决策材料包含全部零交付运行、代码/配置/布局身份，以及“长训练
  预算和性能结论尚未获批”的明确说明。
- [ ] 正式训练 seed 列表为八个配对 seed；正式评估实例表由 `200–209` 各派生 20 个
  不同 episode，跨方法和训练 seed 保持一致。`9300–9302`、`9400–9409` 不进入
  正式比较；持续补货的主指标不使用旧版目标完成率或 `success`。
- [ ] 正式图 5,000 步耐久评估单独预注册 `400–409` 的 10 个实例，四种方法、8 个
  训练 seed 复用相同实例表。结果按每 1,000 步分段，并包含交付、补货、充电恢复、
  能量死亡、碰撞、死锁和实际步数；该评估由负责人在主评估前审批、运行，且与 1,200
  步主比较分开，不据有限时长测试宣称无限运行保证。
- [ ] 统计模板以配对训练 seed 为方法比较单位，先在 seed 内汇总评估实例，再报告
  8 个训练 seed 的配对差异和区间；零事件须标明样本量，不得把重复环境实例当成
  独立训练重复或宣称风险为零。
- [ ] 12/16-AGV 压力评估明确标为待单独批准，列出充电容量和 Actor-only 评估入口
  的前置条件；本轮没有将其结果混入 8-AGV 同规模主比较。

## 核验步骤

1. 独立计算 `docs/formal_environment/environment.json`：总计 1,400 格、504 个货架格、
   896 个非货架可通行格、10 个拣选站、8 个充电站。逐项核对注册布局及站点坐标与
   JSON 完全一致。
2. 对诊断 seed `9300–9302` 分别重置两次，重放同一合法动作序列，比较 AGV、任务、
   电量和事件轨迹；核查包含载货及充电状态的一轮完整交付与立即补货。
3. 逐场景比较训练和评估解析后的环境 manifest；预期差异仅为 seed 及评估专属输出字段。
   核对 200 个正式评估实例 ID 不重复，且四种方法使用同一实例表；另核对 10 个
   耐久评估实例与主比较互不重叠、时长为 5,000 步，且各方法和训练 seed 共用。
4. 尝试用临时配置启动正式长训练，以及跨场景加载 checkpoint；两者都必须在产生运行
   产物或改变模型状态之前失败。
5. 从原始日志重算每组 50k 诊断的累计步数、更新次数、交付数、吞吐量分母及耗时；
   决策材料须纳入失败运行，不得挑选最佳 seed。
