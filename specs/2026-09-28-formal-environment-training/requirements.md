# 需求 — 正式仿真环境训练配置

## 范围

- 核对现有仿真机制，评估拟议的 `50×28` 仓库是否适合作为论文的第三个训练场景。
  本任务制定配置和验证方案，不重新设计环境动力学。
- 准备三个难度递进的训练场景：RWARE 官方 `tiny-3ag`、现有 `medium-5ag`，
  以及 8 台 AGV 的 `50×28` 正式图。前三组训练完成并经审阅后，再单独决定是否增加未见拓扑。
- 将正式图 12/16 台 AGV 的零微调评估列为后续压力测试候选；本轮只记录准入条件，
  不把它们作为新的训练组或已可执行的评估协议。
- 为 baseline、A* KD、LLM KD、A* KD + LLM KD 四种方法制定可比的临时环境、
  MAPPO 和评估配置。
- 形成短测证据及负责人决策材料，供确定最终 `environment_steps`、学习率日程、
  reward 版本，以及 baseline 优化结果要求的必要修订。本任务不启动长训练。

## 不在范围内

- 改变任务分配、优先级语义、动作或观测语义、充电与拣选动力学，以及
  MAPPO、A*、LLM 的职责边界。
- 批量调参，或依据单 seed、50k 步诊断声称策略收敛。
- 训练或评价未见拓扑模型、选择论文获胜方法，或在批准正式协议后依据固定评估结果反向修改协议。
- 在本轮实施 12/16-AGV 压力测试，或未经充电容量设计便把 8 台训练 checkpoint
  直接加载到更多 AGV 的完整训练模型中。
- 读取或修改 `specs/roadmap.md`，修改与本次文档语言要求无关的宪章内容，
  或触碰正在进行 baseline 优化的代码文件。

## 已确认的仿真机制

环境重置时，seed 决定 AGV 初始位置、初始请求货架及后续随机过程。规则层将待办任务随机
分配给空闲 AGV。任务创建时，从打乱的均衡随机袋中获得固定的 A/B/C 优先级；三档权重为
`2.0/1.5/1.0`。AGV 到货架取货，送至拣选站；每完成一单，立即补入一个替代任务，维持
活跃任务池。低电量时由规则层管理充电目标。拣选服务使 AGV 暂停 3 步。MAPPO 在五种
离散动作中选择逐步动作；A* 与离线 LLM 只提供训练监督，执行期不调用在线 LLM。同一场景
的训练与评估采用相同任务负载。上述机制仍须用代码和确定性轨迹核验；不能据此认为新地图
已经注册或可运行。

## 场景合同

| 场景 | 地图来源及大小 | AGV | 充电站 | 拣选站 | 初始活跃任务 | 候选 `max_steps` |
| --- | --- | ---: | --- | --- | ---: | ---: |
| `tiny-3ag` | RWARE 官方 tiny 地图，`10×11` | 3 | `(0,0)`、`(9,0)`、`(9,10)` | 原生两个目标 `(4,10)`、`(5,10)` | 3 | 800 |
| `medium-5ag` | 现有 `llm-mappo-medium-3ag-v1` 地图 | 5 | 沿用现有 5 个 | 沿用现有 2 个 | 5 | 800 |
| `formal-8ag` | `docs/formal_environment/environment.json`，`50×28` | 8 | 使用 JSON 中全部 8 个 | 使用 JSON 中全部 10 个 | 8 | 1200 |

三个场景都采用 `balanced-random-v1`、`rware_delivery`、一个初始任务批次、每完成一单
补入一单，以及固定时长 episode。同一场景的训练和评估使用相同环境参数与随机过程定义，
仅使用预先指定的不同 seed 集。新场景配置不包含旧版 `task_target` 与定时入库字段；加载器
如需向环境构造函数传入默认值，必须核实 `rware_delivery` 下不会产生定时入库，也不能据
`task_target` 提前终止 episode 或计算成功率。主要任务指标为每集完成任务数、每 1,000
实际环境步的完成任务数；同时报告死锁、能量死亡、碰撞和前进受阻事件。

正式地图 JSON 包含 504 个货架格、10 个拣选站、8 个充电站；当前文件 SHA-256 为
`2a03a4abfe281de6865f39399d870f5ba9931d2520a6829bdb01788d50ca22fc`。
直接计数得到 896 个非货架可通行格，其中普通地面 878 格。现有说明误写为 886 个
可通行格，并引用了旧路径 `docs/environment.json`。实施时应更正文档，并核验布局哈希、
站点可达性及完整配送循环。

从静态结构看，对称站点和连通通道使该地图适合作为候选场景；但中央单格宽通道、较长路程
以及站点共享，可能造成 8 台 AGV 拥堵、充电困难或零交付。静态连通不等于策略可训练，
这些风险必须在长训练前测量。

## 临时训练与评估配置

- 使用 16 个 CPU 环境 worker、`rollout_length=64`，每次完整 PPO 更新采集 1,024 个
  累计环境 transition。`environment_steps` 是所有 worker 的累计步数，不是每个 worker
  各自的步数。
- 暂用当前 baseline 的 `ppo_epochs=5`、`num_minibatches=1`、`gamma=0.99`、
  `gae_lambda=0.95`、`clip_param=0.20`、Actor/Critic 学习率 `3e-4`、熵系数
  `0.01`、value loss 系数 `0.50`、梯度范数上限 `0.50`、Huber delta `10`、
  隐层维度 `64`。电量消耗倍率 `1.10`、充电阈值 `0.30/0.80`、死锁阈值 `180`
  也暂作起点；这些值尚未冻结。
- `7/17/27` 只作为前期诊断 seed。正式主比较为四种方法、三个场景规划同一组 8 个
  配对训练 seed：`7/17/27/37/47/57/67/77`。正式评估使用保留的基准 seed
  `200–209`，每个基准 seed 派生 20 个不同 episode 实例，共 200 个；派生规则为
  `episode_seed = 1000 × base_seed + episode_index`，其中 `episode_index=0..19`。
  四种方法及所有训练 seed 复用同一实例表。现有 `9400–9409` 仅为 Group 2 诊断
  评估，准备阶段另用 `9300–9302`，均不得混入正式主比较。正式评估使用相同的固定
  时长任务流、带动作掩码的确定性 argmax PolicyHead；记录执行期 A* planner query
  和在线 LLM 调用数均为 0。
- 正式 8-AGV 场景另列 5,000 步耐久评估，使用与主比较不重叠的 10 个预留环境 seed
  `400–409`，每个 seed 对应一个固定实例。四种方法各自的全部 8 个正式训练 seed
  都在同一实例表上评估，不更新策略；此项共规划 320 个 episode，由负责人在主评估前
  审批并运行。每 1,000 步单独报告交付数和吞吐量，同时报告补货循环、抵达充电站、
  完成充电及充电后恢复任务、能量死亡、碰撞、死锁和实际运行步数。该评估使用正式图
  相同的地图、8/8/10 站点、任务流与评估策略，仅将评估时长设为 5,000 步；结果与
  1,200 步主比较分开呈现。有限时长内持续交付与充电恢复是 lifelong MAPF 能力的
  经验证据，不构成无限运行保证。
- 统计汇总先对每个训练 seed 在同一批环境实例上求均值，再以 8 个训练 seed 作为
  方法差异的不确定性分析单位；报告配对差异和区间，不把 200 个评估实例或耐久评估
  的 10 个实例当作彼此独立的训练重复。零能量死亡或零死锁须同时报告样本量，不能
  解读为风险概率为零。
- 长训练之前，每个场景仅允许一组 seed `7` 的 baseline 诊断，累计环境步上限为 50,000。
  它可用于发现接口故障、零交付行为和估计训练速度，不能证明最终性能。诊断入口必须显式
  确认，并只接受三个临时场景、seed `7`、不超过 50k 步，以及隔离的输出目录
  `artifacts/formal_environment_training/diagnostics/<scene>/seed_0007/`。
  正式训练入口仍须拒绝临时配置。
- 负责人于 2026-09-30 明确采用 tiny/medium/formal 的 `environment_steps` 为
  `450000/900000/1800000`；四组共享同场景预算。优化日程终点与预算相同，学习率
  沿 baseline 线性降至 0；每 25k 保存 checkpoint，并保留预算 50%/100% 里程碑。
  中途 checkpoint 可在越过名义里程碑后保存，身份必须记录实际累计步数。
  短测继续提供接口、学习信号和速度证据，reward 及其余运行准入条件仍待核验。
  任何字段变化都须产生新的配置身份；适用的变化须在四种方法之间保持匹配。
- Group 2 交接给出的优先候选是 medium-5AG 的 C1 energy-death local-mean reward、
  600k 累计环境步、16 个 worker、rollout 64、5 个 PPO epoch 和 1 个 minibatch；
  学习率在 600k 线性衰减至 0，checkpoint 间隔为 25k，保留 300k/600k 里程碑。
  该候选仍为 `provisional`，不能直接当作三个场景的统一预算或已冻结 reward。
- 负责人批准前，配置保持 `approval_status: provisional`。不同场景及观测或 Critic
  维度发生变化时，须使用独立的环境 ID、产物目录和严格的 checkpoint 身份；禁止静默
  迁移或部分加载旧 checkpoint。
- 新配置 schema 为 `three-scene-mappo-provisional-v1`；新环境 ID 为
  `llm-mappo-tiny-3ag-v1` 和 `llm-mappo-formal-8ag-v1`。medium 可沿用现有环境 ID，
  但新配置及 checkpoint 身份必须与历史 medium 运行区分。

## 依据与风险

- 当前 core baseline 使用 6 个 worker，训练 episode 500 步、评估 800 步，且评估
  负载更高。这些是历史起点，不是本规格的三场景合同。当前加载器还固定要求 6 个 worker、
  每台 AGV 对应一个充电站、拣选站数等于 `floor(AGV/2)`；tiny 的两个目标和正式图的
  十个拣选站要求改为按场景核验站点清单。
- 当前 FP Critic 的货架槽位在训练主进程和环境 worker 中都写死为 144，而正式图有
  504 个货架格；必须按已注册布局确定槽位数并核验维度，不能仅替换地图 JSON。
- 交接中的 medium-5AG、seed `7` 的 600k final checkpoint 在诊断评估 seed
  `9400–9409` 上共完成 43 单，但有 42 次能量死亡、4/10 回合死锁、0 次抵达充电站
  和 0 次完成充电。它证明该配置出现非零交付，不证明安全、持续运行或多 seed 收敛。
  同目录本地 YAML 的 `max_steps=1000` 与实际运行清单中的 `800` 不一致，哈希也不同；
  复现时须找回精确配置，或按运行清单重建并生成新的配置身份，不得覆盖原文件。
- 交接指出现有 `success` 和 `task_completion_rate` 不适合解释持续补货：完成一单时
  又新增一单，不能把约 45.8% 当作“25 单目标完成率”，也不能把 `success=0/10`
  直接当作业务失败率。正式协议须版本化修正这些指标，主报告使用原始交付数、实际
  episode 步数和明确定义的每千步吞吐及安全事件。
- 现有 8 个充电站无法直接支持 12/16 台 AGV：环境构造要求充电站数不少于 AGV 数，
  充电目标分配器在无空闲站点时会报错，当前没有排队合同。Actor 输入固定为 209D，
  但 FP Critic 输入随 AGV/货架/站点数变化；因此跨规模零微调评估须先单独批准
  充电容量方案，再用严格校验来源的 Actor-only 推理入口。不得将其等同于原 checkpoint
  在新规模上直接兼容，也不得把压力测试结果当作同规模主比较。
- 正式 JSON 只定义静态布局，尚未在 `rware` 注册；其 AGV 数、任务流和电量设置由本规格
  给定。三份正式地图资料目前在 `core-integration` 中仍未被 Git 跟踪。实施时须将已审阅、
  哈希一致的 JSON 和说明纳入版本控制；独立规格工作树不复制或修改这些文件。
- 用户提供的 MAPPO 原论文支持在困难多智能体任务中采用较少 PPO epoch、尽量不拆分
  minibatch，但没有给出本仓库地图的现成训练步数。论文建议的裁剪范围应结合 baseline
  证据在最终批准前复核；当前不擅自改变继承来的 `clip_param=0.20`。
- medium-5ag baseline 单独零交付不会使正式图停止。若完整的 A* KD + LLM KD 联合组
  在预定的每个训练 seed 上，其各自固定 `9400–9409` 评估的完成任务数总和均为 0，
  才将证据交给负责人决定是否暂停正式图长训练；不自动暂停。
